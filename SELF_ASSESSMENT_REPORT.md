## What we did not manage

- No web interface: the walk-through uses the API (or the Swagger page). A screen comes with the real-time results of PA#5.
- No limit on login attempts yet, and password checks are deliberately slow, so a flood of logins slows the API.
- Every Accepted submission is reviewed, not only the last one before the deadline (FAQ-02), and a deadline is optional, because the walk-through submits several solutions.
- The worker holds the Docker socket to start the sandbox (decision 10); a socket proxy or rootless Docker is not done.
- The model is on the free tier: a burst can hit HTTP 429, which falls back to `unsure` and adds TA work.

## What we would do differently

Deploy on day one and call the model from the VM at once: the first VM's region was refused by Gemini, and we found it only at the first real submission.
